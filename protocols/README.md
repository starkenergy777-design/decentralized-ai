# Protocols

Protocol IDs and schemas are versioned here. The node prototype uses libp2p Identify (`/ai/peer/1`), Ping, and a CBOR request-response protocol (`/ai/task/1`). Its payload contract is in [task-v1.cddl](task-v1.cddl) and is mirrored by Rust and Android. Requests contain a version, positive task ID, operation code, and two signed 64-bit operands. Operation `1` is checked addition. Error codes are `1` invalid ID, `2` unsupported version, `3` unsupported operation, and `4` overflow. Rust rejects unknown fields and sets 256-byte request and response codec limits. Android currently applies the same contract to its local WorkManager demo; P2P transport is not connected to the Android app yet.

The current schema uses only fixed-width numeric values and nulls, with no text or byte-string payload fields. The task worker never executes peer-supplied code. Future schemas must include bounded payload sizes, validation rules, and compatibility behavior. Never serialize secrets or raw biometric samples into a network message.
