# Android app

The Kotlin/Jetpack Compose settings screen is in `app/`. It saves local preferences for opt-in, CPU budget, memory budget, daily network budget, Wi-Fi-only, and charging-only behavior. Participation defaults to off. An opt-in user can enqueue a fixed local `20 + 22` demonstration task through WorkManager. The worker re-checks participation and budgets before executing; turning participation off cancels the queued demo task. WorkManager defers it until the selected unmetered-network/charging constraints and a non-low battery condition are met.

The local task uses the same versioned fields and operation/error codes as Rust's `/ai/task/1` protocol. This is only a local scheduler proof: it does not receive P2P work, run an AI model, enforce an exact CPU percentage, or account for daily network use. The shared Rust networking core will be integrated later through a reviewed JNI/FFI boundary. Android's background-work restrictions mean the node must not assume it can run continuously; use scheduled work for deferrable jobs and a visible, user-started foreground service only for work that must remain active. No attestation or biometric check is implemented.
